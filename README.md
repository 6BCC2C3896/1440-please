# 1440, Please

**Keeps YouTube stable at 1440p.**

YouTube can usually play 1440p. Sometimes it just needs help.

**1440, Please** is a focused Firefox extension built for one job: reach 1440p without repeatedly starving the video buffer, then keep playback stable there.

It does this conservatively. Instead of hard-locking 1440p at startup, it lets YouTube begin at a safer quality, preserves the healthy lower-resolution buffer, opens a soft 1080p–1440p range, and moves upward when the player is ready.

## What it does

- starts cautiously instead of forcing a cold 1440p representation;
- preserves useful buffered media while quality ramps upward;
- prefers 1440p as the final operating quality;
- uses buffer state, real media activity, switch history, and delivery timing to avoid resolution flip-flop;
- keeps the UI deliberately small: **Buffer**, **Quality**, **Stage**, activity, and ramp speed;
- leaves YouTube Shorts untouched.

## Firefox only

This project is **developed and tested for Firefox desktop only**.

- Manifest: WebExtensions MV3
- Current minimum Firefox version: **142**
- Primary development target: Firefox Developer Edition on desktop
- Chromium/Chrome/Edge are **not supported or tested**
- Firefox for Android is **not currently a tested target**

The controller uses Firefox-specific extension behavior and YouTube's internal page player surface. Cross-browser compatibility is intentionally not claimed.

## Install

### Normal users

Firefox Release and Beta require Mozilla-signed extensions. When a signed build is attached to a GitHub Release or published on AMO, download the signed `.xpi` and install it in Firefox.

Until a Mozilla-signed public build exists, use the development install below.

### Development / local testing

1. Clone or download this repository.
2. Open `about:debugging#/runtime/this-firefox` in Firefox.
3. Click **Load Temporary Add-on…**.
4. Select this repository's `manifest.json`.
5. Open a normal YouTube video and click **1440, Please** in the toolbar.

Temporary extensions are removed when Firefox restarts.

For an unsigned packaged XPI, Firefox Developer Edition/Nightly/ESR can also permit unsigned extensions when the appropriate signature setting is disabled. This is for development/testing, not the recommended public distribution path.

See [docs/INSTALL.md](docs/INSTALL.md) for the complete install and signing explanation.

## Controls

There are only two settings.

### Enabled

Turns the controller on or off.

### Ramp speed

**Defensive** is the default and proven profile. It gives YouTube more time to warm the 1440p path before promotion.

**Aggressive** shortens only the upward-promotion gates. It does **not** weaken the protected 1440p transition, real-delivery checks, or failed-trial backoff.

Changing ramp speed does not restart the active quality controller.

## How the quality ramp works

A typical successful session looks like this:

```text
native startup
    ↓
720p / 1080p with a healthy buffer
    ↓
soft 1080p–1440p range
    ↓
YouTube warms the higher representation
    ↓
1440p
    ↓
stable 1440p cruise
```

The extension intentionally avoids treating every temporary low-buffer moment as failure. A cold 1440p path can briefly sit near zero while real media is still arriving. It falls back only when delivery evidence says the path is genuinely failing.

For the controller design, see [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Privacy

**1440, Please does not collect analytics, telemetry, browsing history, or personal data for the developer.**

It observes the current YouTube tab, media-buffer state, and YouTube/Googlevideo request metadata locally so the controller can make playback decisions. It does not send those observations to a third-party analytics service or project server.

See [PRIVACY.md](PRIVACY.md).

## Safety boundaries

The extension deliberately does **not**:

- monkeypatch page `fetch` or XHR;
- rewrite SABR/player-time payloads;
- seek the playing video to manufacture demand;
- run synthetic parallel video downloads;
- modify YouTube watch-time reporting;
- inject a HUD or other visual UI into the YouTube page.

The popup and settings page are the only user interface.

## Development

Requirements:

- Node.js 24 recommended
- Python 3 for deterministic release packaging
- Firefox desktop for manual integration testing

Run everything:

```bash
node tools/test-all.mjs
```

or:

```bash
bash tools/test-all.sh
```

Build release artifacts:

```bash
python3 tools/build-release.py
```

Artifacts are written to `dist/`:

```text
1440-please-<version>.xpi
1440-please-<version>-source.zip
SHA256SUMS.txt
```

The XPI generated by this repository is **unsigned** unless it has subsequently been submitted to Mozilla for signing.

## Tests

The suite covers:

- syntax and dependency closure;
- bootstrap/startup safety;
- buffer calculations and network classification;
- quality-range and MAIN-world bridge behavior;
- soft 1080p→1440p warmup;
- anti-flip-flop and retry backoff;
- ZigZag/cruise behavior and missed-refill detection;
- resume/checkpoint behavior;
- popup/settings contracts;
- forbidden-capability scanning.

CI runs the complete suite and builds the release artifacts on GitHub Actions.

## Releases

Push a version tag such as:

```bash
git tag v0.17.8
git push origin v0.17.8
```

The release workflow verifies that the tag matches `manifest.json`, runs the full suite, builds the XPI/source archive, creates checksums, and publishes the artifacts to a GitHub Release.

**Important:** GitHub packaging does not make an XPI Mozilla-signed. For normal Firefox Release/Beta installation, submit the XPI through Mozilla/AMO signing first. See [docs/RELEASING.md](docs/RELEASING.md).
